# 弹性分段与阅读视图

启动：在 demo 目录运行 `go run .`。修改后需要重启后端，并刷新页面；旧报告不会自动重新转写。

## 音频处理

- 提取单声道 16 kHz PCM 音频后，使用 FFmpeg `silencedetect=noise=-35dB:d=0.5` 检测至少 0.5 秒的低音量区间。
- 目标长度 30 秒，在距当前起点 20～40 秒范围内，优先选择最接近目标的静音区间中点（必要时限制到搜索范围）。
- 找不到合适静音则强制切分；每段最多 40 秒。剩余不超过 40 秒时直接作为尾段，避免再拆；接近音频末尾时为尾段留出至少 8 秒。整个音频本身不足 8 秒仍可正常处理。
- 边界连续、不重叠、不丢弃静音；时间以提取后音频的毫秒位置记录，对应页面播放的相对时间。当前不处理特殊媒体中音轨相对视频的起始偏移。
- 停顿检测失败时明确报错，不悄悄改用另一种策略。低音量检测不是句子识别，也不是说话人分离，背景噪声可能降低效果。

JSON 的 `audio_chunks` 保存所有计划片段，包括没有识别出文字的片段。`segments` 保存有文本的片段，新增 `boundary_reason`：`silence`（停顿处）、`forced_limit`（强制）、`end_of_audio`（音频结束）。这些原因描述片段的结束边界。

## 页面和证据

转写过程中先按原顺序接续展示。转写结束后额外调用一次配置的文本模型，读取所有相邻原始分段，调整跨段标点、普通英文段首大小写，并决定在哪些块边界结束阅读段落。该调用会增加等待时间，可能计费，不需要新 API Key。

后端严格校验整理结果的分段数量、ID、顺序及字词，拒绝增删词、改写变量、数字、术语、口头重复或新增时间字段。只允许有限句子标点、空白与普通英文块首大小写调整；它是保守的字词校验，不证明模型语义判断正确。单字母变量、全大写缩写、拼音声调、小数等有专门测试。段落来源由后端从原始 ID 构造，不让模型生成时间。校验失败、HTTP 403 或流中断时，整份阅读整理退回原文接续并显示原因类别提示，不自动重试，不阻断原始证据的六维分析。

每组保留各片段回看按钮。原始分段视图显示实际时间与切分原因。六维分析同时得到原始分段和整理段落，仅用后者辅助内容理解；节奏与表达判断不能据整理后的流畅文字做出。下载 JSON 的 `reading` 包含状态、说明、逐段整理记录、阅读段落及请求元数据；`segments` 始终是原始转写。原词校验不能证明标点或语义正确，仍需人工复核。

当前只在原始块之间选择阅读段落边界，尚不做块内精细语义分段。未实现句级时间戳、自动词语纠正或局部重听 ASR。需要改词时可保存人工转写修订并重新分析，原始 ASR 版本保留。疑似拼音、英文、网址纠正不得冒充原话，也不能据此评价教师发音。

## 验证

运行 `go test -v ./...` 和 `go vet ./...`。覆盖静音日志解析、选择停顿、连续无静音、短尾段、全静音和完整覆盖。若 FFmpeg 在 PATH 中或设置了 `FFMPEG_PATH`，额外生成含已知静音的合成音频验证检测；否则该项明确跳过。测试不调用百炼，不产生模型费用。

真实课堂评估：用同一个已授权视频比较旧版与新版的句中截断数、术语错字数、分段数量以及回看位置。停顿阈值是起始设置，不能视为识别准确率已经提高的证明。

阅读整理验证：`go test -v ./...` 包含矩阵定义跨段合句、中文拼音、保护数字/变量/网址、拒绝遗漏与未知来源，以及本地假服务的成功、403、截断和非法输出测试。`node --test tests/transcript.test.cjs` 验证阅读/原文切换、回看、失败提示与新任务清理。所有这些测试无需真实密钥，不调用百炼。
