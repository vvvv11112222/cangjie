# 第一、二阶段交付说明

本文保留早期设计背景；当前运行方式和版本以 README.md 为准。当前生成期采用维度内事件选择协议，由服务端构造正式报告的事件与原文关联；默认还增加一次全文检查。下文早期调用次数和字段说明不能替代当前协议。

## 第一阶段：六维标准与样例基线

`rubric.md` 是 `six-dim-text-v1` 标准。它为每个维度定义可观察指标、事件类型映射和禁止推断范围：内容、节奏、思维、表达、管理、技术均可证据不足；系统不输出能力分数。`events_prompt.txt` 只提取教学事件，不直接写评价。每个事件必须包含原始分段的逐字引文、事件类型、关联维度和不确定性说明。

当前代码校验：事件引文必须是对应原始分段的连续子串；事件 ID、类型、维度映射和分段来源不能重复或伪造。事件最多 80 条，避免模型把普通句子全部变成事件。

## 第二阶段：事件到报告

处理顺序为：弹性音频切片 → 原始转写 → 阅读整理 → 教学事件提取 → 六维报告。报告模型同时接收 `original_segments`、`reading_paragraphs`、`teaching_events` 和 `rubric_version`。阅读版只辅助理解，原始分段仍是证据来源。

报告观察必须填写 `event_ids`。后端检查：事件属于观察维度；事件引用的全部原始分段都出现在观察的 `evidence_ids` 中；证据不足维度不能生成观察。已有旧报告格式如果缺少 `event_ids` 会被拒绝，这是为了防止看似完整但无法解释的报告混入系统。

页面在六维报告前展示“教学事件与证据”，列出事件摘要、不确定性和对应的原始音频回看按钮。下载 JSON 保存 `events`、`rubric_version`、事件请求元数据和报告。

## 一次任务的实际阶段

1. ASR：按停顿规划 20～40 秒范围内的音频块。
2. 阅读整理：文本模型判断相邻块是否属于同一句；后端保守地整理标点。
3. 事件提取：文本模型依据 `rubric.md` 抽取可观察教学事件。
4. 六维报告：文本模型只基于事件和原始证据生成摘要、亮点、问题及建议。
5. 校验：来源、维度、状态、事件和证据链全部通过后才发送结果。

阶段 3、4 使用同一个 `BAILIAN_TEXT_MODEL`，每个视频任务通常需要三次文本请求（阅读整理、事件提取、六维报告），另加每个音频块各一次 ASR 请求。如果项目需要节省调用次数，可以在稳定性评估后合并阅读整理和事件提取；当前拆开是为了便于测试和展示证据链。
