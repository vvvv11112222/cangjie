# 前端 UI 约定

这份文件只讲**展示层怎么写**，目的是让 React 页面与仓库提供的[系统草图](../系统草图.html)保持同一套信息结构、布局和视觉语言。
系统草图是页面模板，不是数据或权限实现；接口、字段、枚举、权限和错误码仍然以 [开发协议](../docs/开发协议.md)、[端点映射](../contracts/endpoints.json) 与 [Schema](../contracts/v1.schema.json) 为准。

技术栈：React 19 + Vite + TypeScript，样式是唯一的全局文件 `src/styles.css`，没有 CSS 框架、没有 UI 组件库、没有图标库。

## 0. 模板与实现的边界

- 页面名称、角色入口、侧栏分组、页头层级、筛选区、卡片和表格布局以 `系统草图.html` 为模板；不要另起一套导航或视觉结构。
- 草图中的记录和交互都是浏览器内演示数据。React 页面只展示固定协议样例或 Go HTTP API 返回的数据，不能把草图数据复制成业务结果。
- 草图中的按钮必须同时满足“协议有端点”和“资源 `allowed_actions` 允许”才可实现。角色菜单只控制入口可见性，不能代替服务端授权。
- P1 页面可以展示规划关系，但必须标明尚未接入，不能伪造实时设备、行为识别或趋势结果。
- 页面正文使用人能理解的中文；协议字段、哈希和锁版本不在业务页面罗列；排错时按需展示诊断信息。

## 1. 颜色和形状只用 `:root` 变量

所有颜色、圆角、阴影都定义在 `src/styles.css` 的 `:root` 里。**页面和组件里不要写十六进制颜色**，一律写成 `var(--xxx)`。

常用变量：

| 用途 | 变量 |
| --- | --- |
| 侧边栏、主按钮 | `--brand`（悬停 `--brand-hover`） |
| 强调色：选中、运行中 | `--accent`、`--accent-soft`、`--accent-text` |
| 页面背景 / 卡片 | `--bg`、`--card` |
| 边框 | `--line`（更明显的一档 `--line-strong`） |
| 文字 | `--ink`（主）、`--muted`（次）、`--faint`（字段名、编号）、`--ink-body`（正文段落） |
| 悬浮面 / 下沉面 | `--surface-hover`、`--surface-sunken` |
| 圆角 | `--radius-card`（卡片）、`--radius-control`（按钮、输入框） |
| 卡片阴影 | `--shadow-card` |

需要新颜色时，先在 `:root` 里加一个带注释的变量，再引用它；不要在页面里就地写死。

## 2. 状态一律用 `Tone`

状态色只有 6 档，定义在 `src/format.ts` 的 `Tone`：

| 色调 | 含义 | 图标 |
| --- | --- | --- |
| `green` | 成功、已完成、就绪 | 圆勾 |
| `teal` | 运行中、分析中 | 时钟 |
| `amber` | 需注意：部分完成、证据不足、复核中 | 时钟 |
| `red` | 失败、已删除、已撤回 | 感叹号 |
| `gray` | 排队、跳过、取消、草稿、已归档 | 圆点 |
| `blue` | 中性信息：观察、ASR、示范数据 | 信息 |

渲染用 `BadgeTag`（带图标，用于状态）或 `Pill`（纯文字，用于分类和操作标签），不要在页面里手写 `color: green` 这类样式。

新增一种业务状态时：先在 `format.ts` 对应的映射表里加一条，再从上面 6 档里选一个色调。**不要新增颜色。**

**页面上的错误和限制怎么显示**：带错误码和失败阶段的结构化错误用 `RunErrorBox`；一行说明性提示（批次限制、结果限制、批次读取失败、轮询失败）用 `.notice-strip`。这两种就是全部，不要自己再拼第三种提示样式。

## 3. 应用外壳与新页面

应用外壳固定由 `App.tsx` 渲染：宽屏左侧栏、顶栏面包屑、账号入口、主内容和页脚。页面不能自行复制这些结构。

1. 在 `src/roleNav.ts` 的 `NAV_GROUPS` 登记菜单、角色和顺序；没有独立菜单的辅助地址放在辅助路由清单；
2. 在 `src/App.tsx` 的 `NAV_ICONS` 配图标，在 `PAGE_RENDERERS` 注册页面组件；
3. 页面最外层用 `<div className="page">`；
4. 标题区用 `<header className="page-head">`，只放 `h1`（页面名）与必要状态，不加英文副标题、宣传语和通用说明；主操作放在标题区右侧；
5. 内容分区用 `Card`（可选 `icon`、`subtitle`、`actions`）；筛选条件放在统一工具栏，表格必须套 `.table-wrap`；
6. 字段用 `Field`，编号用 `IdChip`，空态用 `EmptyState`，加载/失败用 `LoadStateNote`。

角色与模板的入口必须一致：系统管理员查看全校管理入口；学院教务查看本学院人员、教务、课堂和来源；督导查看课堂、任务、报告、来源、操作记录和设备规划；教师只查看本人课堂相关入口。转写属于课堂复核流程，不在侧栏重复增加模板外入口。

## 4. 页面减负与独立引导

业务页面仅保留操作、数据结果、筛选、状态与真实错误。删除重复指导、英文副标题、宣传语、占位流程图和接口字段清单，不用折叠区继续堆放。

新用户说明集中在 `#/help`，按实际角色提供教务准备、课堂选择、上传、来源核验、视觉、语音、结果和报告步骤。首次登录仅询问一次；可以跳过，右上角随时重开。主动点击“去操作”时高亮对应控件，返回帮助时清除。引导不自动提交任务或修改权限。

许可与费用选择、不可逆操作确认、失败原因和当前数据范围仍应出现在作出对应决定的位置。模型、版本和原始协议数据保留在服务端及 JSON 等适合追溯的输出中。

## 5. 按钮与输入控件

| 场景 | 写法 |
| --- | --- |
| 主操作（一个区域最多一个） | `.btn .btn-primary` |
| 次操作 | `.btn .btn-secondary` |
| 危险、不可逆操作 | `.btn .btn-danger`，并且放在最右，和主操作拉开距离 |

按钮必须对应真实功能。没有接口支撑的操作不要做成按钮，也不要为了好看加按钮。

输入框和下拉框都放进 `.account-field`，尺寸、边框、圆角和聚焦态由它统一提供——`input` 和 `select` 必须长得一样。新增别的控件类型（日期、多选等）时，记得一起补 `:focus` 态，否则会露出浏览器原生外观。

## 6. 窄屏

全站 React 实现只有一个主断点：`@media (max-width: 900px)`，规则是“侧栏变成顶部导航区”。草图里的 1200/980/760 是原型实现细节，不照抄成第二套断点体系。

新页面只需要保证两件事：

- 表格套在 `.table-wrap` 里（内部横向滚动，不撑破页面）；
- 横向排列的卡片用 flex 并允许 `overflow-x: auto`（参考 `.stage-flow`）。

**整页不允许出现横向滚动条。** 改完在 1280 / 1024 / 820 三档宽度各看一眼。

## 7. 复用与依赖

- 公共组件都在 `src/components/ui.tsx`，图标在 `src/components/icons.tsx`；
- 两个页面用到同一块 UI 时，抽到 `ui.tsx`，不要在页面里复制一遍；
- 不新增依赖。需要图标就手写内联 SVG（参考 `icons.tsx` 的写法）。

## 8. 提交前

在 `frontend/` 目录运行：

```powershell
npm run check
```

它会依次做类型检查、单元测试和构建。

改了按钮、输入控件、焦点样式或 `<details>` 折叠区时，再跑一次键盘/焦点探针（零依赖，用本机 Edge）：

```powershell
# 先在 frontend/ 下构建并启动支持 Range 的预览服务
npm run build
npx vite preview --port 18768
# 再从仓库根目录执行
node frontend/tools/a11y-probe.mjs http://127.0.0.1:18768
```

它检查 Tab 顺序、焦点是否可见、`<details>` 能否用键盘展开，并在真实布局里量一遍控件尺寸——
这些是单元测试（jsdom 不算布局）证明不了的。

`src/pages/pages.test.tsx` 里断言的页面文案（例如"阶段完成 4/6"）不要为了视觉好看删改；确实要改文案时，测试一起改，并在提交说明里写清楚。
