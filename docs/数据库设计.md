# 教学质量管理系统数据库设计

文档 v0.6，2026-10-03。目标数据库为 PostgreSQL 17 系列。结构由 [001](../database/001_initial_schema.sql)、[002](../database/002_review_baseline.sql)、[003 整改迁移](../database/003_review_fixes.sql)共同定义，检查见 [check_schema.sql](../database/check_schema.sql)。新库按编号执行；旧库停写并备份后仅执行未应用的迁移，禁止重跑或改写历史迁移。

## 1. 建模范围

P0 共29张表，覆盖身份、教务、媒体、任务、证据报告与治理。数据库保存业务记录和文件索引，文件字节存媒体存储。主键使用 UUID，审计流水使用 bigint identity；业务时间为 timestamptz，播放位置为整数毫秒。

外键、唯一约束和 CHECK 保证结构一致性；权限、跨行状态转换与证据语义由 Go 检查。JSONB 保存配置快照及算法元信息。数据库连接只授予 Go，迁移账号与业务账号分开。

列名、类型、默认值和索引以 SQL 为准；本节只说明业务含义。

## 4. 一致性与事务

### 4.1 排课与媒体

排课使用 btree_gist 和三个部分排斥约束，区间为 [start,end)，相邻时段允许，cancelled 不占用资源。教师、班级副本通过复合外键与开课实例一致。应用将 SQLSTATE 23P01 转为 SCHEDULE_CONFLICT；批量导入整批回滚，跨学院错误不透露对方详情。旧库存在重叠课表时须先处理，002 不自动删记录；003 遇到已有开课、课程、班级不在同一有效学院时也整体回滚，须明确修正归属后再升级。

003 的 college_of 沿组织父链解析学院；开课、课程、班级必须同学院，教师必须为 active 且具 teacher 角色。跨学院教师安排仅系统管理员可操作，角色与权限仍由 Go 检查。组织移动、基础资料学院变更须在引用检查和锁内执行；有开课引用时不得通过移动组织/课程/班级间接改变历史归属。教务操作账号时必须检查其全部角色绑定，不能管理本人、含系统/教务管理员角色或含其他学院授权的账号。

有课表无课堂时，锁开课及其课表，在事务内 SET CONSTRAINTS fk_schedule_offering_resources DEFERRED，同步修改开课与所有课表教师/班级，再 SET CONSTRAINTS ... IMMEDIATE；三个排斥约束仍须通过。已有课堂则开课归属不可改；已关联课堂的课表开课、教室、起止时间不可改，取消保留旧记录，后续使用新安排。创建课堂也锁开课和选定课表，避免与变更竞态。

source_records 与 media_assets 使用 (source_record_id,session_id) 复合外键；不允许借用另一课堂的许可。003 对共享或错配的历史来源按课堂拆分为 pending，不复制有效许可；原登记信息复制到新记录，原核验保存在 legacy_verification，旧 ID 到新 ID 映射记入最小审计。无媒体且无归属的历史来源仍隔离，由管理员 assign-session。派生媒体检查根原媒体、任务、租约和同课堂归属，不能仅检查资产 ID 存在。

时间点查询为 starts_at ≤ at 且 ends_at > at；时间段查询为 starts_at < query_end 且 ends_at > query_start。查询不能替代数据库对并发写入的冲突裁定。

替换主媒体时锁课堂，取消旧主标记后指定 ready 新媒体；历史批次仍绑定旧资产。object_key 由存储适配器生成，拒绝用户路径和任意存储键。SQL 保证 start_ms 非负、end_ms 大于 start_ms，应用再检查原媒体时长上界和时间映射。

### 4.2 转写与报告

保存转写修订时锁课堂并检查 transcript_lock_version，插入快照头与全量片段后递增版本；课堂初始版本为0。片段须非空、编号连续、时间有效，父版本必须为同课堂同媒体的较早修订。

content_sha256 由 Go 对按 segment_no 排序、字段依次为 segment_no/start_ms/end_ms/text_content/speaker_label 的紧凑 UTF-8 JSON 数组计算，关闭 HTML 转义且不附尾换行。按同规则从落库片段重建核验，Python 无需重算。

full/media_prepare 不带修订输入；report_only 必须绑定同课堂、同媒体快照。input_sha256 仍为原媒体摘要，config_hash 固定 mode、修订 ID/摘要及模型配置。report_only 将快照复制为新批次片段并重建证据，provenance 记录 source_revision_id/source_segment_no。media_prepare 只建 probe，源媒体 playback_asset_id 在 probe 成功事务确定，可指向本身或同课堂 proxy；旧 ready 媒体缺指针须重新 probe 后才能给播放地址。流程见[架构第4节](系统架构设计.md#4-转写证据与报告)。

模型候选暂存 job_artifacts.metadata.report_candidate，仅供 Go validate 使用；校验后才创建草稿。报告 lock_version 从1开始；更新须带版本，不匹配返回 REVISION_CONFLICT。published、superseded、withdrawn 内容只读。parent_report_id 仅关联同批次修订，跨批次历史按 session_id 查询。

report_dimensions.coverage 在003后直接保存与 API 相同的区间数组。旧空对象转为空数组；非空旧对象没有可靠映射，迁移会整体回滚，须由数据负责人先确认映射，不能丢弃原内容。报告/维度 summary_evidence_ids 由 Go 校验同批次且当前可用；模型候选还必须属于实际模型输入清单，人工编辑引用按同批次可用证据检查。非事实说明写 limitation。整份内容确认保存 content_sha256、reviewed_content_sha256、reviewed_by/at，发布触发器拒绝未确认的新发布；历史发布事实不伪造确认。正文变化清除确认，所有报告写入原子递增 lock_version。

观察 ID 保持稳定，PATCH 移除观察使用 removed_at，不能物理删除并重建；复核外键禁止普通删除带走历史。完整课堂清理仍可在同一事务删除报告及其复核/观察。publish 在课堂锁内比对 expected_current_report_id（首次发布为null），再切换当前版；不同草稿发布也检测陈旧预期。新增转写不自动修改旧报告。

报告 content_sha256 使用第4.5节规范化 JSON，对 summary、summary_evidence_ids、dimensions、provenance、observations 计算；observations 保留响应顺序和 ID，排除 review_status，已 removed 的观察不在正文中。数组保留顺序，复核状态、时间和 allowed_actions 不参与内容摘要。参考实现见 tools/contract_rules.py 的 report_digest。转写摘要仍按本节前述片段字段顺序计算，二者不要混用。

发布事务先锁课堂，再检查权限、六维、复核与证据，将旧 published 改为 superseded 后发布新版本并写审计；失败整体回滚。数据库限制维度代码和每维最多一行，应用负责六维齐全、每条保留观察有证据及发布后不可改。

### 4.3 任务领取与完成

以下示例由 Go 为 Python Worker 领取媒体阶段，参数为新租约 UUID 和 worker_id；实际 stage 还须与服务凭据能力求交集。

```sql
WITH candidate AS (
    SELECT j.id
    FROM teaching.analysis_jobs j
    JOIN teaching.analysis_runs r ON r.id = j.run_id
    JOIN teaching.lesson_sessions s ON s.id = r.session_id
    JOIN teaching.media_assets m ON m.id = r.media_asset_id AND m.session_id = s.id
    JOIN teaching.source_records src ON src.id = m.source_record_id AND src.session_id = s.id
    WHERE j.status = 'queued'
      AND j.stage IN ('probe', 'audio_analysis', 'video_analysis')
      AND j.available_at <= now()
      AND j.attempts < j.max_attempts
      AND r.status IN ('queued', 'running')
      AND s.status NOT IN ('deleting', 'deleted')
      AND s.content_expires_at > now() AND m.expires_at > now()
      AND m.status IN ('pending','ready') AND src.rights_status = 'verified'
      AND src.allowed_uses ? CASE WHEN r.mode='media_prepare' THEN 'playback' ELSE 'analysis' END
    ORDER BY j.priority DESC, j.available_at, j.created_at
    LIMIT 1
    FOR UPDATE OF j SKIP LOCKED
)
UPDATE teaching.analysis_jobs j
SET status = 'running', attempts = j.attempts + 1,
    worker_id = $2, lease_token = $1::uuid,
    lease_expires_at = now() + interval '120 seconds',
    execution_deadline_at = now() + make_interval(secs => $3::integer),
    expected_execution_sha256 = $4,
    updated_at = now()
FROM candidate c
WHERE j.id = c.id
RETURNING j.*;
```

示例只锁任务；完成、取消和删除事务按课堂→批次→任务加锁，领取事务不反向获取课堂锁。领取提交后可条件更新批次为 running，不能覆盖取消状态。Go 后台以同样方式领取 evidence/report/validate；重试、回收和阶段依赖见[架构第5节](系统架构设计.md#5-任务阶段状态与恢复)。

示例 $3 为 Go 按阶段固定的硬期限秒数（不得小于租约时长），$4 为固定 Execution 的摘要，不能由 Worker 覆盖。Go 阶段另外按所需用途过滤，report 发出前重新检查 external_processing_allowed。完成事务还检查原媒体、课堂到期、当前许可、storage_generation 和实际执行版本。任务已 succeeded 时，以 last_completed_token 和 completion_digest 识别重复确认；其他情况要求 running 且当前租约有效。首次完成保存结果与确认摘要、清空租约并创建后续任务，同事务提交。

### 4.4 预算

预算预留按账期、币种串行化，可使用事务级 advisory lock。锁内汇总实际费用和未结算预留，按固定价格版本与最大 token 预留后写 model_calls。网络调用在事务外。unknown 不释放预留；实际费用超出预留时暂停新调用并核对。

003 固定 billing_period 为预留时的上海自然月，并保存 price_version、request_sha256。跨月发送前尚未 dispatch 的预留必须在两个账期的锁内重新计入新月后才能发送；一旦 dispatch_started_at 持久化，不再更换账期。call_key 为 report job_id 的稳定字符串，每个报告任务最多一条调用。dispatch_started_at 必须在网络请求前提交，之后崩溃按可能已计费处理，禁止自动重发。reserved/unknown 无 actual_cost/settled_at；succeeded/failed 必须有非负实际费用及结算时间，failed可以已收费。仅明确未发送或供应商确认未收费时结算0；错误类别本身不能证明未计费。

跨月预算锁按账期升序取得。标记 dispatch 的事务按课堂→来源→批次→任务加锁并复查许可，标记提交是进入在途调用的边界；边界后撤权即使网络发送尚未返回，也只能停止采纳结果并继续对账，不能证明调用未发生。来源核验/撤销使用相同锁顺序递增 rights_version；不允许先锁来源再反向取课堂锁。

管理员以 lock_version、供应商请求标识、核对依据和实际金额进行对账，写 reconciled_by/reconciliation_reason 与审计；费用明细不含课堂文本。未知账目阻止同一未解决调用的重新生成；普通用户不能通过新键或新批次绕过，管理员确认旧调用已结算后才解除。清理不删除账目，核对入口不依赖课堂仍存在。历史不符合结算规则的记录保持原事实，启动前检查并对账，不能凭迁移填入0。

### 4.5 幂等与后台治理

批次唯一键为 (requested_by,session_id,idempotency_key)，导出为 (requested_by,report_id,idempotency_key)，清理为 (requested_by,session_id,idempotency_key)，不同动作使用不同表。request_sha256 是原客户端请求的规范化摘要，不能用运行时 config_hash 替代；字段按字典序递归排序、紧凑 UTF-8 JSON、不转义非ASCII/HTML、无尾换行。Go在事务中保存摘要；迁移前缺摘要的记录仅供历史查询，不重放为新的请求。重放也须重新检查当前访问权限。

导出/清理在Go治理执行器领取，不进入Python领取集合；各用 executor_id、lease_token、lease_expires_at、attempts、available_at。领取、续租和完成都比较当前token及课堂代次。导出过期租约清除暂存文件后重排，达到配置次数则failed；清理从 cleanup_manifest 最近完成步骤继续，缺少回执/备份处置条件时blocked并设置下次检查，条件恢复后领取。执行失败重试耗尽则failed，课堂保持deleting；管理员以新幂等键提交清理请求，复用同一课堂删除事实和先前清单，各请求的 tombstone_id 仍唯一。每步操作幂等，文件不存在视为已删除，读取失败不得视为已清理。

## 5. 到期与删除

期限以[项目文档第6节](../项目文档.md#6-运行安全与验收)和 [.env.example](../.env.example)为准。Go 创建报告时取默认报告期限与课堂 content_expires_at 的较早值；派生媒体不晚于父资产，导出不晚于报告期限。读取与导出均检查课堂及报告到期时间。

媒体到期后更新证据 availability，历史报告可保留文字并标注不可回看；导出仍须有 export 许可，不提供失效播放链接。归档不等于删除。

课堂清理由 data_deletion_requests 编排：

1. 先将随机 tombstone_id、课堂ID及请求时间写入独立删除日志并fsync；再锁课堂，递增 storage_generation 并置 deleting、撤销访问，取消任务和租约。两者之间崩溃时，启动必须先重放日志完成撤销，日志失败不返回202。
2. 停止旧代次写入，清理并核验服务端与Worker暂存、媒体、导出和备份；等待活跃写入结束或租约/写入期限失效，执行最终对账。无法联系的Worker或不可核验备份使请求blocked。
3. 同事务将所有 model_calls 的 run_id/job_id 同时置 NULL，按外键依赖删除报告、证据、转写快照、产物、任务、批次、媒体及来源。
4. 课堂置 deleted，移除原始标题等内容，保留外键所需的结构引用和最小审计事实。

修订与批次存在可延迟复合外键，清理事务使用 SET CONSTRAINTS ALL DEFERRED 后一起删除两侧。模型账目保留请求标识与金额供独立核对；unknown 的预留继续占用原账期预算，不阻塞课堂内容清除。

cleanup_manifest 记录逐步结果、Worker清理确认和备份覆盖，只允许治理读取。所有上传和导出先在不可公开访问的随机暂存区写入，最终登记/移动前在课堂锁内复查 storage_generation、状态、期限及当前租约；旧代次文件不能登记，仍须删除。未清完保持blocked，不能只因为数据库无媒体行就标记succeeded。独立删除日志位于 DELETION_LEDGER_PATH，排除在业务库快照回滚之外；保留到所有更早备份销毁且超过审计期限。恢复时保持ready=false，载入最新日志、重放删除并对账后才开放访问，日志缺失不能启动读服务。用户此前合法下载且脱离系统控制的副本不承诺远程擦除。模型候选与转写快照同属课堂内容。
