# 安卓手机采集操作与验收

2026-10-23补充：手机入口已增加iPhone Safari兼容路径，包括缺少setCodecPreferences时限制实际SDP为H.264/Opus、兼容请求超时/取消、可选音量与常亮能力。安卓与iPhone均需可信HTTPS、前台亮屏和双权限；iPhone不要使用微信内置浏览器。手工安装根证书描述文件后，还须按[Apple官方说明](https://support.apple.com/en-us/102390)在“设置 → 通用 → 关于本机 → 证书信任设置”开启根证书完全信任。团队网页部署可生成仅含公共CA的mobileconfig，不包含CA私钥、设备管理或账号。安装后打开capture-check.html检查双设备。**本次代码兼容测试不替代安卓或iPhone真机验收，两种手机仍待操作者实拍确认。** 可选直播框见[实时采集接口](实时采集接口.md)第6节。

## 1. 入口与分工

电脑仍访问 `/capture-demo.html`，负责创建、恢复活动采集和观看。Go 返回的 `phone_url` 格式保持 `/capture-demo.html#pairing_token=…`；该入口把手机配对访问转到同源 `/capture-phone.html#pairing_token=…`。手机页读取后立即清除 fragment，交换只通过请求体进行。手机无需登录教师账号。前端以后提供正式电脑业务页时，原样打开后端 `phone_url` 即可，不要自行拼接凭据或改写业务路由。

手机入口为独立 Vite 构建入口，不注册到电脑导航，也不加载电脑账号上下文。两份 HTML 和构建的 assets 必须一起部署；不能只复制 public 目录或只部署 index.html。开发仍使用项目既有 Vite 服务，代理与媒体可达配置遵循[实时采集接口](实时采集接口.md)。

相关实现：[手机控制器](../frontend/src/capture/phone.ts)、[WHIP 协商](../frontend/src/capture/whip.ts)、[手机页面](../frontend/src/capture/phone-entry.ts)。未新增账号、任务系统、媒体缓存或长期凭据存储。配对、发布、控制凭据只保存在本次页面内存，不写 URL 查询参数、日志、Web Storage 或诊断信息。刷新或浏览器销毁页面会失去这些信息，须回电脑停止原采集并重新创建；返回缓存页面也不会自动续接。

## 2. 联调前由后端准备

1. 电脑与安卓手机处于同一 Wi-Fi，后端提供实际可信 HTTPS 地址、已准备的课堂和核验通过且具备 playback 用途的来源。不能使用未授权测试来源冒充可采集课堂。
2. 按[实时采集接口](实时采集接口.md)配置 Go、数据库001～009、MediaMTX v1.15.3、Worker 和 HTTPS 代理。手机应能访问网页、业务 API、WHIP 信令与实际媒体 UDP8189；控制 API 和 `/internal/` 不公开。
3. 后端提供匹配域名或局域网 IP 的公共 CA 证书与指纹；操作者核对后在安卓设置中安装 CA 公共证书，并用实际浏览器访问 HTTPS 页面确认受信任。不同机型安装菜单不同；不传输 CA 私钥，不关闭浏览器安全检查。若页面在证书错误处已被拦截，页面代码不能代替证书安装，应按本步骤处理。
4. 前端使用 `VITE_DATA_SOURCE=api`，电脑用既有账号登录。确认 `/capture-phone.html` 可直接返回构建页面，API 返回 JSON、媒体 POST 返回 SDP；代理应暴露并正确重写 `Location`。若媒体为另一 HTTPS 域名，后端负责 CORS、证书与 Authorization/Location 响应头配置。

## 3. 手机操作

1. 电脑创建本次采集并取得新配对链接，把链接通过受控方式交给同 Wi-Fi 的手机，不交给外部二维码或分析服务。
2. 手机打开链接，保持供电，横放并对准讲台或纸面文字；点击“开始采集”，同时允许后置摄像头和麦克风。页面优先申请1280×720、15fps，设备不满足时显示实际参数与调整提示，不将目标参数当成实际结果。页面只保证交换返回的课堂 ID，不假定存在课堂名称。
3. 手机预览始终静音。观察“麦克风输入活动”：获得音轨、检测到输入活动是不同状态。电平采用真实输入波形 RMS，不代表收音清晰或 ASR 结果。若电平不可用，页面明确提示在电脑试听；拒绝麦克风或缺少任一轨道时不发布。
4. 区分本地预览、媒体正在连接与下方“上次服务端确认”。只有服务端 `recording` 表示正在录像，仍需核对服务端两条轨道；轮询失败会提示状态无法确认。页面每1.5秒安排一次不重叠查询，请求超时12秒，不能凭本地预览判断录制成功。
5. 保持页面前台、手机供电和屏幕开启。屏幕常亮请求失败或被释放会提示手工延长熄屏时间；不承诺锁屏或后台持续采集。浏览器/系统造成轨道暂停、断流、切后台或断网会结束本次采集，不自动创建第二条连接。
6. 点击“停止采集”即释放摄像头、麦克风、音量节点、常亮与 WebRTC，同时请求 Go 停止并使用 WHIP 返回资源执行 DELETE。202只表示收尾中，继续等待 `finalizing → ready`。停止失败时按钮变成“重试停止”，本地保持关闭；电脑也可恢复并停止原采集。关闭页面的网络请求仅尽力发送，最终依赖 Go 断流检查和对账，不能视为录像已保存。
7. `ready` 后记录正式 `media_asset_id` 和 `media_prepare_run_id`，回电脑试听与回放首尾，再进行课后分析。不要将浏览器预览、手机缓存或模拟测试 ID 交给 Worker 作为正式分析输入。

## 4. 故障处理与协商边界

| 现象 | 操作 |
| --- | --- |
| 权限拒绝或被安卓收回 | 在浏览器站点权限和安卓应用权限中允许摄像头、麦克风，关闭其他占用应用；已交换配对的采集须先回电脑停止再新建 |
| 配对过期、已消费或交换响应丢失 | 不重试同一 token；回电脑停止当前采集，再新建采集及配对 |
| 视频有画面但没有音频 | 不算完整音视频成功；检查麦克风权限、输入电平、电脑静音与服务端轨道，必要时停止重建 |
| 网络不可达或连接超时 | 核对可信 HTTPS、同一 Wi-Fi、VPN、代理和 UDP8189；本轮不自动续接时间轴 |
| 安装证书后，HTTP连接指南和HTTPS设备检测页均打不开 | 先检查手机到电脑的网络；校园网可能隔离同网段设备。尝试电脑连接手机热点，由部署端停止旧采集、更新监听IP及防火墙本机地址后重启，再生成新链接。具体操作见[团队网页部署](../deploy/team-web/README.md#在原团队网站启用手机采集与直播框) |
| 本地停止但服务器不可达 | 保留页面控制信息后重试停止；若已刷新则从电脑恢复/停止，等待后端对账 |
| 不支持兼容编码 | 更新安卓 Chrome 或请后端明确兼容方案；不静默切换成未知可录制性格式 |

WHIP 使用同一连接的两个 sendonly 轨道，严格选择浏览器实际支持的 H.264/Opus，检查 SDP answer 未拒绝音/视频且包含兼容编码，再通过 outbound RTP stats 记录实际编码。完整 ICE 收集最多10秒；SDP POST最多15秒，收到201、SDP与同媒体路径的 Location 后建立连接，SDP完成后15秒仍未连接则停止。页面不做 PATCH、ICE restart 或自动重连。

协议核对依据：[WHIP RFC 9725](https://www.rfc-editor.org/rfc/rfc9725.html)、[codec preferences 浏览器文档](https://developer.mozilla.org/en-US/docs/Web/API/RTCRtpTransceiver/setCodecPreferences)、[MediaMTX v1.15.3 HTTP 实现](https://github.com/bluenviron/mediamtx/blob/v1.15.3/internal/servers/webrtc/http_server.go)。本仓库代理的实际公网/局域网连通与录像兼容性仍需后端及真机共同验证。

## 5. 可复现检查与本轮记录

使用 Node 24，安装项目锁定依赖后在 frontend 运行：

```powershell
npm ci
npm run check
```

在仓库根目录运行文档检查：

```powershell
python tools/check_docs.py
```

手机单元测试位于 [phone.test.ts](../frontend/src/capture/phone.test.ts)，覆盖权限拒绝、缺少音轨、过期/已消费或响应丢失的交换、重复开始停止、等待权限/交换时停止、停止失败重试、ICE完成/取消/超时、断线、轨道回收、切后台、轮询失败与终态、编码和 Location 校验。所有 API、设备与服务端数据为合成对象。

另有使用已安装 Playwright 的[浏览器探针](../frontend/tools/phone-capture-probe.mjs)，不向项目新增依赖。先构建，并分别在两个终端运行：

```powershell
python -m http.server 18767 --bind 127.0.0.1 --directory frontend/dist
```

```powershell
node frontend/tools/phone-capture-probe.mjs http://127.0.0.1:18767 <已安装的Playwright包目录>
```

探针默认使用 Windows Edge，可通过 EDGE_PATH 指定兼容 Chromium 可执行文件。使用模拟摄像头/麦克风、浏览器内模拟的 WHIP/JSON 接口与真实 WebRTC 回环；**未连接实际 Go/MediaMTX 录像**。结果与截图位于本地忽略目录 `var/phone-capture/`，模拟媒体标识明确带有 synthetic，不属于正式媒体 ID。

本轮 `npm run check` 通过26个测试文件、205项测试（其中手机采集22项），类型检查与双入口生产构建通过；文档检查通过159个协议样例、92个端点映射及17份文档。既有电脑页面的键盘/焦点探针全部通过。

2026-10-15 实测：Node24.19.0、桌面 Edge155.0.4283.45；模拟设备得到1280×720、15fps、单声道48kHz，outbound stats为 video/h264 与 audio/opus。浏览器验证旧入口跳转、清除fragment、不泄露凭据、静音双轨与电平、重复开始、停止失败后硬件释放和重试、终态与刷新指引，以及离线、切后台、页面离开释放硬件且无第二发布者；1280/1024/820/390/360宽度无整页横向溢出，按钮与键盘焦点检查通过。模拟设备不提供真实后摄型号，也不能证明拍摄/收音质量。
