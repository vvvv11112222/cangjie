# B0：Windows 电脑与安卓手机联调环境

适用范围：一台 Windows 电脑、一部安卓手机、同一 Wi-Fi。启动真实 Go、PostgreSQL、MediaMTX、probe/video Worker、API 模式前端及 HTTPS 网关。B0 交付环境；真实手机录制 1～3 分钟属于 B1，ASR、视觉协议扩展和真实报告属于后续阶段。接口规则见[实时采集接口](实时采集接口.md)。

## 1. 依赖与配置

需要 Go 1.26、PostgreSQL 17、Node.js 24+、Python 3.12（按 [Worker 说明](../workers/README.md)安装 `workers/requirements.lock`）、MediaMTX **v1.15.3**、支持 WHIP 的 FFmpeg/FFprobe（本机验证 8.1.2）、Caddy **2.10.2**。使用发行方二进制并核对校验和；Caddy 该版本官方 checksums 文件使用 **SHA-512**。采集 FFmpeg 与 Worker wheel 附带的 FFmpeg 是两个用途，不能互换摘要。

从仓库根目录操作：

```powershell
New-Item -ItemType Directory -Force var/capture-dev | Out-Null
Copy-Item deploy/capture/dev-tools.example.json var/capture-dev/tools.local.json
```

编辑 `tools.local.json`，把每个路径改为本机实际安装位置，`python` 必须指向装有 Worker 锁定依赖的虚拟环境。`node` 与 `npm_cli` 填写各自实际文件；不依赖 PowerShell 对 `.cmd` 的转义。填写电脑 WLAN 的 IPv4 地址，手机不能使用 localhost。

```powershell
python tools/capture_dev.py prepare --ip <电脑局域网IPv4> --tools var/capture-dev/tools.local.json
python tools/capture_dev.py start
python tools/capture_dev.py trust
python tools/capture_dev.py status
```

`prepare` 构建 5 个 Go 程序、执行 `npm ci` 并以 `VITE_DATA_SOURCE=api` 构建前端，初始化独立数据库，应用所有尚未执行的迁移（当前 001～009），初始化删除账本及测试账号。完成后数据库关闭，`start` 启动整套服务。环境仅位于此 checkout 的 `var/capture-dev`，不读取其他项目的数据库 URL、不重置现有库、密码或被撤销的来源权限。再次准备前须停止本环境。换 IP 后用新 IP 重新 prepare/start；CA 保留，站点证书自动匹配新地址。

所有服务在后台运行，无需保留终端。`trust` 显式将本环境 CA 加入**当前 Windows 用户**的根证书存储；Caddy 使用 `skip_install_trust`，不会自动改系统信任。安装后重启已有浏览器以刷新证书信任。证书机制见 [Caddy TLS 文档](https://caddyserver.com/docs/caddyfile/directives/tls)和[全局配置](https://caddyserver.com/docs/caddyfile/options)。

如果由 AI / 任务管理终端启动，终端可能在会话结束时清理子进程。此时将 `start` 换成 `start-detached`，使启动器脱离终端的 Windows Job。它不提权；若终端策略不允许，改在普通 PowerShell 中执行 `start`。启动记录见 `launcher.log`。`stop` 对两种启动方式相同。

## 2. 地址和交接文件

| 服务 | 监听位置 | 访问范围 |
| --- | --- | --- |
| HTTPS 前端、API、WHIP/WHEP | 电脑 LAN IP:8443 | 同一 Wi-Fi |
| 仅公共 CA 下载 | 电脑 LAN IP:8081 | 同一 Wi-Fi，不提供登录或媒体 |
| WebRTC 媒体 | 电脑 LAN IP:8189/UDP | 同一 Wi-Fi |
| Go API | 127.0.0.1:8080 | 本机 |
| MediaMTX 信令 / 控制 API | 127.0.0.1:8889 / 9997 | 本机 |
| 独立 PostgreSQL | 127.0.0.1:15436 | 本机 |

网关不转发 `/internal/*`。媒体通过 `/media/*` 代理并重写 WHIP/WHEP 返回的 Location。前端从构建产物提供服务；编辑前端后要重新 prepare/build，不是 Vite 热更新模式。端口占用时脚本报错，不会停止其他服务。

启动成功后，在本地查看：

- `var/capture-dev/handoff.json`：构建时代码 SHA、是否有未提交变更 `source_dirty`、HTTPS/采集页地址、公开 CA 下载地址和 SHA-256 指纹、课堂/来源 ID、依赖版本；真机状态初始为待验证。
- `var/capture-dev/accounts.private.txt`：四个开发账号及初始随机密码。单独通过受控渠道交给对应成员，不能放进公开文档或 PR。
- `var/capture-dev/private.json`：数据库、Worker、控制和事件独立随机凭据；只保留本机，不能分发。
- `var/capture-dev/public/capture-ca.crt`：唯一允许分发的 CA 公共证书。**不要发送 `caddy-storage`，其中包含 CA 私钥。**

运行目录整体被 Git 忽略，但忽略规则不等于文件加密；使用自己的 Windows 用户目录权限，不共享整个仓库运行目录。提交代码后重新 prepare 会更新交接 SHA。不要人工修改已生成的密码来“重置”账号，它不会修改数据库中的现有密码。

## 3. 安卓证书与设备检查

1. 手机和电脑连接同一 Wi-Fi。在手机 Chrome 输入交接文件中的 `ca_download` 地址，下载 `capture-ca.crt`。如浏览器不下载，可通过 USB 只复制这一文件。
2. 在安卓“设置”搜索“安装证书”，选择 **CA 证书**（通常位于安全 / 更多安全设置 / 加密与凭据），按系统要求输入锁屏密码，安装该文件。不同品牌菜单不同。安装前后核对证书 SHA-256 指纹与 `handoff.json`；无法显示指纹时，通过 USB 传输电脑已核对的证书。
3. 完全退出并重开 Chrome，访问 `https://<电脑IP>:8443/capture-check.html`。必须没有证书错误，页面显示“HTTPS 安全环境检查通过”。不要点击“仍然继续”，也不要禁用安全检查。
4. 点击“检查摄像头和麦克风”，允许两个权限，确认能看到画面，讲话时音量条变化；点击“结束检查”，确认系统摄像头/麦克风占用图标消失。
5. 将上述四项结果交给负责人记录。环境检查不上传、不录制，也不代替 B1 服务端录制验证。

B0 在这项人工检查完成前只能标为“电脑端已验证、安卓待确认”。交接文件里的 pending 标记不会因为电脑自动化测试通过而自行变成完成。

## 4. 防火墙与网络

只在 Windows 防火墙拦截时，由电脑管理员开放本环境的三个端口，限定本地子网，不关闭防火墙。下面命令在管理员 PowerShell 中执行，替换为真实 IP；规则名已存在时检查并更新，避免重复创建：

```powershell
$captureIP = '<电脑局域网IPv4>'
New-NetFirewallRule -DisplayName 'Cangjie B0 HTTPS' -Direction Inbound -Action Allow -Protocol TCP -LocalAddress $captureIP -LocalPort 8443 -RemoteAddress LocalSubnet
New-NetFirewallRule -DisplayName 'Cangjie B0 public CA' -Direction Inbound -Action Allow -Protocol TCP -LocalAddress $captureIP -LocalPort 8081 -RemoteAddress LocalSubnet
New-NetFirewallRule -DisplayName 'Cangjie B0 WebRTC' -Direction Inbound -Action Allow -Protocol UDP -LocalAddress $captureIP -LocalPort 8189 -RemoteAddress LocalSubnet
```

无需开放 15436、8080、8889、9997。校园 / 访客 Wi-Fi 可能隔离设备，即使 SSID 相同也不可互通；确认手机能打开 CA 下载地址和 HTTPS 页。不要将这些开发端口映射到公网。

## 5. 账号、课堂与权限

种子只创建一套虚构课堂和自录测试来源，实际 ID 在 handoff 中。用于开发者本人或已同意参与者的测试，不代表真实课堂授权。来源初始 verified，允许 `playback`、`analysis`，`external_processing_allowed=false`。重新 prepare 不恢复被撤销的权限。

| 账号 | 角色与操作 |
| --- | --- |
| teacher_demo | 本课堂任课教师；创建、配对、停止、观看、回放 |
| supervisor_demo | 同学院督导；观看及内容读取，不能创建采集 |
| academic_demo | 教务管理员；管理课堂 / 来源，不自动获得观看或采集权限 |
| admin | 系统管理；仅用于管理和排障，不用它代替角色验收 |

先在 HTTPS 根页面用 `teacher_demo` 登录，再打开 `/capture-demo.html`，填写 handoff 的两个 ID。创建采集后，将页面生成的短期配对链接交给手机打开。手机点击开始；电脑点击观看，按需开启声音。停止后等待 `ready`，回课堂详情查看正式媒体和回放。活动采集可通过“恢复当前活动采集”恢复查看。

Worker 真实执行 probe/video，不实现 ASR。当前 Go 启动校验要求三个阶段的配置槽位，环境将 ASR 名称/版本明确写为 `not-installed`，Worker 只注册 `probe,video_analysis`；这不会产生转写。报告预算为 0，任何外部模型调用保持关闭。请勿以 full 分析结果来验收本阶段。

## 6. 停止、升级和排障

先在采集页停止录制并等待 ready/failed，再执行：

```powershell
python tools/capture_dev.py stop
python tools/capture_dev.py status
```

有 waiting/recording/finalizing 采集时 stop 会拒绝，防止中途丢录制。停止只处理本脚本记录且 PID、启动时间、可执行路径一致的进程；PostgreSQL 使用 pg_ctl 正常停机，数据库和媒体保留。升级代码时依次 stop、拉取代码、prepare、start。不要在运行时删除 `var/capture-dev` 或单独删除账本、私钥、数据库、凭据。

| 现象 | 检查方法 |
| --- | --- |
| prepare 失败 | `setup.log`，核对工具路径、网络、锁定依赖；保留原目录修复后重试 |
| ready 不通过 | `api.log`、`postgres.log`，检查迁移、账本、端口占用 |
| 手机无法打开网页 | Wi-Fi 隔离、IP 变化、TCP 防火墙、caddy.log |
| 网页可开但连接不到画面 | UDP8189、防火墙、mediamtx.log，确认电脑地址与生成配置一致 |
| 403 或来源不允许 | 账号角色、课堂归属、来源 playback 许可；不要跳过后端校验 |
| 一直 finalizing | worker.log、api.log、FFmpeg/FFprobe 路径、worker 执行版本；查看真实错误字段 |
| 日志显示音频未实现 | B0 仅 probe/video；真实 ASR 按后续分工接入 |

自动检查入口：`python tools/check_docs.py`、`python -m unittest discover -s tools -p test_capture_dev.py`；真实链路回归见[实时采集接口](实时采集接口.md)第 5 节。自动化合成摄像头验证、手机人工验证分开记录，不能相互替代。
