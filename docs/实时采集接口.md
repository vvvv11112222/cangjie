# 手机实时采集接口与联调

本功能对应 FR-12 的单课堂、单次连续连接版本：安卓手机在同一 Wi-Fi 中发布音视频，电脑实时观看，停止后将录像送入既有 `media_prepare`。断流结束当前采集；再次录制创建新采集和新原媒体，不自动合并断流前后的时间轴。ASR、OCR、行为和报告仍走课后分析。

## 1. 运行准备

1. 使用 Go 迁移工具执行完整001～009迁移，旧库仅执行未应用迁移；配置启用既有 probe Worker。正式资产和录制暂存目录分别管理。
2. 准备 MediaMTX **v1.15.3**、FFmpeg 和 FFprobe。示例配置见 [MediaMTX](../deploy/capture/mediamtx.yml)及[HTTPS 代理](../deploy/capture/Caddyfile.example)。本机测试使用的 FFmpeg/FFprobe 版本另记录在验收结果中，不替换 Worker 固定的执行版本。
3. 将电脑局域网 IP 写入 HTTPS 站点地址、`PUBLIC_ORIGIN`、`CAPTURE_PUBLIC_URL`、`CAPTURE_MEDIA_URL` 和 MediaMTX 的 `webrtcAdditionalHosts`；允许手机访问 HTTPS 入口和 UDP8189。API 和控制接口只监听本机，代理不暴露 `/internal/`。
4. 在电脑及安卓浏览器信任该 HTTPS 入口的证书链，证书必须匹配实际访问地址。使用示例Caddy内部CA时，从其实际数据目录的 `pki/authorities/local/root.crt` 取得根证书，核对指纹后传到手机，在安卓设置中搜索“安装CA证书”并安装，具体菜单依机型而异；不传输CA私钥。手机访问电脑的局域网 HTTP 地址不适用 localhost 例外，不使用关闭安全检查的方式接入。
5. 在本地 `.env` 中设置 `CAPTURE_ENABLED=true`，生成独立随机 `CAPTURE_CONTROL_TOKEN`、`CAPTURE_EVENT_TOKEN`，各至少32字符，与 Worker 凭据不同。设置实际 `CAPTURE_FFMPEG`、`CAPTURE_FFPROBE` 路径。其他参数及默认限额见[配置模板](../.env.example)。
6. 从仓库根目录执行 `go build -o var/bin/capture-hook.exe ./cmd/capture-hook`；MediaMTX 也从此根目录运行。hook 会读取本地 `.env`；`CAPTURE_EVENT_URL` 指向本机 Go API，录制根目录必须与媒体服务配置一致。
7. 启动 Go、现有 Worker、MediaMTX、前端与 HTTPS 代理。前端启动时设置 `VITE_DATA_SOURCE=api`，使用同源 `/api/v1` 登录，避免停留在固定样例模式。功能未配置时八个新路由返回 `SERVICE_UNAVAILABLE`，原 P0 链路继续工作。

MediaMTX 配置关闭 RTSP/RTMP/HLS/SRT/公开回放，发布者不能互相顶替；管理 API 也通过 Go 回调鉴权。实际媒体仍使用专门的 WebRTC 通道，不经过业务 JSON。

## 2. 接口目录

业务 JSON 沿用 `{data,request_id}` 和既有错误响应。新 DTO 见 [Schema](../contracts/v1.schema.json)、[端点目录](../contracts/endpoints.json)及[合成样例](../contracts/examples/capture-cases.json)。旧 Worker 的 schema_version 保持1.1。

| 方法与路径 | 认证/输入 | 成功响应 |
| --- | --- | --- |
| POST /api/v1/sessions/{id}/live-captures | 原用户会话、Origin/CSRF、Idempotency-Key；CreateLiveCapture | 201新建/200幂等重放，LiveCapture |
| GET /api/v1/sessions/{id}/live-captures/active | 原用户会话；无请求体 | 200 LiveCapture；当前无活动采集时404 |
| POST /api/v1/live-captures/{id}/pairings | 原用户会话、Origin/CSRF；Empty | 201 CapturePairing |
| POST /api/v1/capture-pairings/exchange | 一次性 pairing_token；CaptureExchange | 200 CapturePublisher |
| GET /api/v1/live-captures/{id} | 原用户会话或本采集 control_token | 200 LiveCapture |
| POST /api/v1/live-captures/{id}/viewer-sessions | 原用户会话、Origin/CSRF；Empty | 201 CaptureViewer |
| POST /api/v1/live-captures/{id}/stop | 原用户会话及CSRF，或本采集 control_token；Empty | 202处理中/200已终态，LiveCapture |
| POST /internal/v1/streams/auth | MediaMTX本机原生回调；StreamAuth | 204，不返回JSON包装 |
| POST /internal/v1/streams/events | 独立事件服务Bearer；StreamEvent | 204，不返回JSON包装 |

创建请求是 `{"source_record_id":"已核验来源UUID","config_profile":"phone-demo-v1"}`。空写请求发送 `{}`。用户侧创建、配对、停止沿用原上传权限（系统管理员或任课教师）；观看沿用内容读取权限，教务管理权限不自动等于观看权限。

创建检查来源归属与 playback 许可。相同用户、课堂、幂等键和参数返回同一采集；不同参数返回 `IDEMPOTENCY_CONFLICT`，同一课堂其他活动采集返回 `CAPTURE_ACTIVE`。活动采集包括 waiting、recording、finalizing，由数据库唯一索引保护。

配对默认5分钟有效，新配对替代未消费旧配对；已交换的发布者不能重新配对抢占，需停止并新建。手机取得 `publish_token`、`control_token`，电脑另取 `view_token`；三者的用途隔离，使用 `Authorization: Bearer ...`。查询不会返回这些秘密、内部文件路径或管理凭据。配对交换全局最多30次/分钟；这是单机保护，不作为多实例共享限流。

发布和观看凭据只允许指定流。MediaMTX 原生接口通过 WHIP/WHEP 的 SDP POST 建立连接，Location 资源后续用于 PATCH/DELETE；代理保留媒体响应及重写子路径。不能把这些信令 URL 当作视频标签 src。

## 3. 状态与恢复

`waiting → recording → finalizing → ready`，不可恢复错误进入 failed。连接和录像状态分别返回，轨道及实际时长未知时为 unknown/null。非空服务端录制文件与真实流状态共同确认 recording。

- `ready`：正式媒体登记成功，现有 media_prepare 批次 succeeded；不代表分析完成。
- `finalizing`：停止意图已经持久化，断开媒体连接、等待尾段、整理文件或等待 probe。重复停止返回同一对象。
- `recording_state=cleaned`：收尾或失败后的录制暂存与连接已经清理，正式媒体仍通过原接口访问。
- `media_asset_id`、`media_prepare_run_id` 给出已有系统的接入点；原媒体仍按原规则选择主媒体，不覆盖既有主媒体。

后台每秒检查连接、文件和权限，处理 waiting 超时、断流和最大录制时间。停止拒绝新发布并关闭已有连接；观看凭据到期、账号/角色失效、来源撤权等也会触发后台断连。网络或媒体服务不可达时保留待处理状态，恢复后重试，不冒充停止成功。

hook 提交 online、offline、segment_started、segment_complete；event_id 幂等，相同ID不同内容返回 COMPLETION_CONFLICT。回调失败可有限重试，后台通过媒体控制 API 和受控目录对账弥补遗漏。单连接一旦断开，不允许换连接继续同一采集。

收尾有持久化租约、最多3次尝试和总截止时间。重启可重新领取失效租约；媒体登记与采集绑定在同一事务，创建 media_prepare 使用固定幂等键。规范化期间持续复查授权、删除状态和租约，失败即停止子进程。文件异常、超限或时间轴不可靠时失败，不登记空录像。

错误包括 CAPTURE_NO_MEDIA、CAPTURE_FINALIZE_FAILED、CAPTURE_FINALIZE_TIMEOUT、CAPTURE_PREPARE_FAILED。终态失败不自动新建分析批次；需查看错误并在恢复条件后新建采集。SOURCE_NOT_VERIFIED、RESOURCE_EXPIRED 等沿用原有含义。

删除流程必须等媒体连接、录制暂存及在途收尾结束；未配置采集适配器或尚有占用时进入 CAPTURE_CLEANUP_PENDING。迟到事件与旧存储代次不能恢复媒体写入。MediaMTX 的独立自动删除关闭，由 Go 生命周期统一清理。

## 4. 前端和视频成员联调

最小客户端：[capture-demo.html](../frontend/public/capture-demo.html)。正式页面开发可复用同一调用顺序；移动端开始按钮才请求硬件权限，本地预览静音，监听声音由用户点击开启。测试页不依赖外部二维码服务，电脑显示可复制的配对链接，手机通过消息或手工输入打开。

手机配对访问现转到同源 `/capture-phone.html` 独立构建入口，后端 `phone_url` 格式不变；桌面创建和观看继续使用联调页。手机操作、异常恢复、模拟测试边界及待执行的真机验收见[安卓手机采集操作与验收](安卓手机采集操作与验收.md)。部署时同时发布两个入口和构建 assets。

1. 电脑在系统登录后打开同源 `/capture-demo.html`，输入课堂ID和已核验来源ID，创建采集并取得手机链接。页面刷新后可按课堂恢复 `waiting`、`recording` 或 `finalizing` 的活动采集；终态采集不再作为活动采集返回。
2. 安卓手机在同一 Wi-Fi 打开链接，点击开始并同意摄像头和麦克风权限，保持页面在前台。
3. 电脑在该测试页点击观看，确认画面与声音。轮询采集状态，不能把本地预览当成服务端正在录像。
4. 任一有停止权限的端点击停止，等待 finalizing 到 ready，再用原课堂回放页或媒体 content 接口回放、拖动进度。
5. 后续分析继续调用原 analysis-runs，Worker 仍经 jobs/input 读取同一正式原媒体，统一以其起点的整数毫秒定位。

视频成员检查手机实际编码、音轨、合并后的相对时间和 probe 代理映射。演示目标为1～3分钟中文讲话和动作视频；电脑自动合成流验证与安卓真机验收分别记录，真机尚未验证时必须标记待验收。
