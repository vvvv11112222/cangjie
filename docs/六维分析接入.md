# 教师六维分析接入主项目

本次接入对应 FR-08，复用主项目的 `evidence → report → validate → draft → 人工复核 → 发布` 流程。音频仍由原 Worker 转写，报告仍由 Go 调用模型。独立 demo 不作为公开报告服务运行，也不将旧 demo 报告套上新 UUID 导入正式课堂。

## 已接入的能力

- 原生中文提示词 `teacher-sixdim-v1`：六维分工、教师讲解思路、事实与推断区分、具体建议和可观察的效果；外语课堂也用中文解释。
- 原有 `ReportCandidate` 字段承载分析：维度 `summary` 写课堂分析，`observation_text` 写具体观察及原因，`suggestion` 写做法、课堂示例和观察效果。同一问题集中在最相关维度，避免每维重复建议。
- 教师报告页保留课堂概览，左侧选择维度，正文依次展示课堂分析、观察/问题、实施建议和依据。正文和建议直接可见，技术 ID 收进技术详情。
- 单一“查看依据”入口展示课堂描述及原录像时间。回放读取所选报告证据自己的媒体，复用主项目媒体鉴权和播放地址预检；跨批次/跨课堂/跨媒体引用不提供回放入口，过期依据保留文字说明。
- 原有权限、来源许可、预算、单次调用、未知计费处理、锁版本和人工复核发布机制继续生效。新模板的问题条目必须带建议；不满足时校验失败，不自动付费重试。

本次没有修改公共 DTO、数据库结构或 Worker 协议，也不新增前端依赖。主项目不接收 demo 的扩展字段。独立 demo 的连续阅读、教学事件中间产物、停顿切片和长课分块调用未整体移植；离线转换工具仍见 [demo 接口适配说明](../demos/ai-language-analysis/integration/README.md)。

## 启用方式

1. 在主项目根目录核对编译内置模板的版本与摘要：

   ```powershell
   go run ./cmd/report-prompt
   ```

   这个命令不读取 `.env`，不连接数据库，不调用模型。提示词文本位于 [teacher-sixdim-v1.txt](../internal/analysis/prompts/teacher-sixdim-v1.txt)，通过 Go embed 打入程序。该文件固定 LF 换行，跨系统获得相同摘要。

2. 在主项目的受控配置中设置命令输出的 `REPORT_PROMPT_VERSION` 和 `REPORT_PROMPT_SHA256`。新安装可参考 [.env.example](../.env.example)，已有 `p0-v1` 部署需要显式选择新版；不因升级自动改变已有批次。

   建议 `REPORT_MAX_INPUT_TOKENS=8000`、`REPORT_MAX_OUTPUT_TOKENS=6000`。较长输出用于保留具体建议，不要求模型用满额度。输出上限也会增加费用预留，须结合供应商价格与月预算设置。现有启动配置还需固定模型修订、选择策略和价格版本；预算为 0 时仍不调用报告模型。本次不复制独立 demo 的 API 密钥或自动开启付费配置。

3. 按 [主项目启动说明](../README.md)启动 Go、原有 Worker 和前端，在已核验并允许分析、外部处理的课堂使用原有“提交分析”，或先校正转写再“用此版本重新生成报告”。请求的 `config_profile` 仍为 `p0-v1`；它是流水线配置，区别于报告提示词版本。

4. 教师查看课堂详情中的报告页。草稿可按资源返回的操作编辑、提交复核，由有权限的复核者逐条处理并确认整篇后发布。新模板不会绕过这个过程。

新版模板摘要错误或版本不存在时，启用报告能力的 API 在启动时拒绝配置；服务内部创建新报告批次时再次检查。旧批次执行其已保存的模板，不随当前配置切换；新版快照还会核对保存文本与摘要。已发布报告不会自动重写，切换提示词后要创建新批次。

## 覆盖与结论边界

主项目当前使用现有的有界证据选择策略：超过输入额度时截短文字或跳过后续证据，并固定实际发送的文本、摘要、引用清单与覆盖。因此，支持上传长录像不等于全部转写都进入了一次模型请求。报告页会在概览前显示截短/跳过提示，结论只能针对实际输入覆盖。不能用这条链路宣称已经完成独立 demo 那样的整节长课分块分析。

机器校验覆盖字段、引用归属、覆盖区间和新版问题是否带建议；它不能证明结论语义正确、建议确实有效或模型遵守了所有提示词。没有学生回答时不能推定学生不会；纯文本不能确定音量、注意力、板书或工具使用效果。证据不足的维度保留原因，不强凑负面问题。

## 自动验证与人工验收

基础检查：

```powershell
go test ./...
go vet ./...
python tools/check_docs.py
cd frontend
npm ci
npm run check
```

数据库集成测试必须使用可清空的独立 PostgreSQL 测试库：现有测试会清理合成业务表，禁止使用教师数据库。设置 `TEST_DATABASE_URL` 后，在仓库根目录执行：

```powershell
go test -p 1 ./... -count=1
```

新增 `TestTeacherReportNativePipeline` 使用本地模拟模型，实际经过请求构造、预算记账、候选校验、草稿持久化和鉴权读取，检查建议、提示词快照及复核要求。前端回归覆盖维度切换/键盘操作、直接展示建议、原媒体毫秒回放、换报告清除旧回放、过期证据和错误授权。这些测试不调用付费模型，不代表真实模型教学质量通过。

真实浏览器回归入口为 [report-browser-regression.mjs](../frontend/tools/report-browser-regression.mjs)：先以 `VITE_DATA_SOURCE=api` 构建并启动 Vite preview，再从仓库根目录运行 `node frontend/tools/report-browser-regression.mjs <已安装的playwright/index.mjs> <预览地址> <本地结果目录>`。脚本拦截业务 API，仅提供合成报告及仓库合成视频，检查 1280/1024/820 宽度、导航键盘操作、原媒体时间跳转与撤销播放授权后的阻断；结果目录含 JSON 和截图，不提交课堂数据。可用 `EDGE_PATH` 指定本机 Chromium 浏览器。

参赛前仍需：获准使用的真实中文课堂及人工参考；中文转写 CER 和时间 P95；学科教师对证据与建议的逐条核对；实际供应商的模型参数、输出长度、耗时和费用验证；Linux/Docker 运行验收。质量测量入口和门槛继续沿用 [开发与验收计划](开发与验收计划.md)，不能以合成测试替代。
