# 数据库联合验收与交接

日期：2026-10-13。范围：FR-03、FR-06、FR-09、FR-11 的数据库与后端事务边界。分支 `database/fr03-fr06-fr09-fr11` 基于后端阶段 7 提交 `9dc251d`；先集成其 001～006，再应用本次 007，不改写历史迁移。

## 1. 交付

- [007](../database/007_validate_runtime_constraints.sql)：验证任务硬截止、模型结算、导出租约、删除租约四项历史约束。任一异常使整个迁移回滚；不会伪造租约、结算时间或零费用。
- [迁移执行器](../internal/database/migrate.go)：已执行历史必须是当前迁移文件的连续前缀；缺失文件、摘要变化和中间缺号的历史拒绝继续。
- [结构检查](../internal/database/readiness.go)：核对完整迁移历史及四个关键约束。API 在启动后台任务前执行；readiness 持续检查，未升级、约束缺失或未验证时拒绝就绪。
- [账号分权](../database/configure_roles.sql)：已有专用角色分别用于迁移与业务；业务角色可读写业务表和使用审计序列，只读迁移历史，无建表、删表或修改迁移历史权限。默认权限覆盖后续迁移新增对象。
- [原生验收](../tools/check_database.mjs)、[升级测试](../internal/database/acceptance_integration_test.go)与[真实 HTTP 发布测试](../internal/httpapi/phase4_integration_test.go)：使用独立 PostgreSQL 17 数据库，不访问课堂媒体或真实模型。
- [数据库 CI](../.github/workflows/database.yml)：固定 PostgreSQL 17.6，运行 Go 集成、竞态检查、原生多连接测试、完整 PGlite 迁移、文档检查、静态检查和构建。

## 2. 本地复现

准备两个独立、可清空的 PostgreSQL 17 数据库：`cangjie_database_acceptance` 和 `cangjie_backend_acceptance`。数据库验收脚本会删除前者的 teaching schema 与迁移历史；后端测试会清空后者的业务表。禁止使用共享开发库或生产库。原生脚本还创建两个 NOLOGIN 验收角色，因此验收账号需具创建角色及调整对象所有者权限；业务账号不可用于运行这些测试。

Node 使用已有 `pg@8.16.3`、`@electric-sql/pglite@0.5.8` 包目录；测试依赖保存在仓库外或被忽略的 var 中，不修改前端依赖锁。Go 使用 1.26.0。Python 文档检查需要 jsonschema。

```powershell
$env:DATABASE_ACCEPTANCE_URL = '<专用 cangjie_database_acceptance 连接串>'
$env:DATABASE_ACCEPTANCE_ALLOW_RESET = '1'
$env:TEST_DATABASE_URL = '<专用 cangjie_backend_acceptance 连接串>'
go test -p 1 -count=1 ./...
go test -p 1 -race -count=1 ./internal/database ./internal/httpapi ./internal/academic
node tools/check_database.mjs '<已安装的 pg 包目录>'
node tools/check_schema.mjs '<已安装的 PGlite 包目录>'
python tools/check_docs.py
go vet ./...
go build ./cmd/...
```

原生脚本只接受固定数据库名及显式 reset 开关，核对服务器为 PostgreSQL 17，并在 var/database-acceptance/sql-results.json 保存不含凭据和课堂正文的结果。两套 Go 环境变量均未设置时相关集成测试会 skipped，不得将这种运行记为联合验收通过。

## 3. 升级和账号分权

升级前停写并备份，用迁移账号执行 `go run ./cmd/migrate`。007 失败时读取 PostgreSQL 返回的约束名，核查对应表的历史行：运行任务须有硬截止和执行摘要；已结算调用须有真实费用与结算时间；导出 running 和删除 processing 须有完整租约，非活动状态须清空活动租约。依据原账单及任务事实修复后重跑；不要删除历史或填写假值以绕过。

旧库若只有 teaching schema、没有 public.schema_migrations，执行器仍拒绝猜测版本。数据库负责人须对照原始执行文件、结构及校验摘要确认基线，再登记实际已执行迁移；本交付不自动生成历史版本。

部署管理员先通过受控配置创建两个专用角色，迁移角色非 superuser，业务角色无超级用户、建库、建角色、复制或绕过 RLS 权限，且不能继承迁移角色。在已迁移数据库以管理员执行分权脚本：

```powershell
$env:PGOPTIONS = '-c cangjie.migration_role=teaching_migrator -c cangjie.app_role=teaching_app'
psql -d teaching -v ON_ERROR_STOP=1 -f database/configure_roles.sql
Remove-Item Env:PGOPTIONS
```

账号密码由部署密钥管理配置，不写入 SQL。迁移命令使用迁移账号，API 的 DATABASE_URL 使用业务账号；迁移账号须始终作为后续对象创建者，才能应用对应默认权限。若原库的 PUBLIC 或其他继承角色仍授予业务账号建表权限，脚本会回滚并要求先处理这些旧授权。当前开发 Compose 共用账号的入口保留；正式部署使用独立连接配置。
