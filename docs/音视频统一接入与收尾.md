# 音视频统一接入与收尾

更新：2026-10-21。面向一台电脑、一个媒体Worker的开发/演示环境。前端通过Go API操作，Worker不直连数据库或云模型。新增011迁移支持同一音频任务的切片独立记账，保留报告任务的一次调用约束；不改写001—010历史。

## 已接通的流程

上传获准录像 → Go创建full批次 → Python probe/播放代理 → 音频与关键帧阶段 → Go保存转写修订与证据 → 六维报告候选与校验 → 前端人工复核 → 发布 → 授权导出。

音频Worker调用现有语言模块的worker-plan命令，复用停顿检测解析及20—40秒切片规则；Go复用同一ASR请求格式，关闭ITN并传递语言提示。音轨按录像公共T0抽取，保留前导静音，不把延迟声音整体移到0秒。返回块级时间，最长40秒；不声称句级定位或说话人区分。

独立Demo继续保留自己的网页、连续阅读、长课分窗和全文审计。主系统接入的是ASR及现有正式报告流程，没有把Demo本地JSON队列迁为业务数据库，也不承诺两个入口输出逐字相同。主系统仍会按固定模型输入预算选取证据，并在报告中保留覆盖限制。

## 模型与费用配置

密钥只放Go进程或本机私有配置文件。Worker只需要内部凭据、模型名称/修订、本地切片工具和FFmpeg摘要，不需要ASR_API_KEY或REPORT_API_KEY。

默认团队视觉启动器不调用收费服务。若要启用统一流程，在数据目录内创建`analysis.private.json`（保留在本地，勿提交或发送给队友），所有值用字符串。下面是字段模板，模型、接口和价格须替换为你已获准使用的实际值：

```json
{
  "ASR_CLOUD_ENABLED": "true",
  "ASR_API_BASE": "https://YOUR-ASR-ENDPOINT/v1",
  "ASR_API_KEY": "YOUR-LOCAL-SECRET",
  "ASR_MODEL_NAME": "YOUR-ASR-MODEL",
  "ASR_MODEL_REVISION": "YOUR-PINNED-REVISION",
  "ASR_LANGUAGE_HINTS": "zh,en",
  "ASR_PRICE_VERSION": "YOUR-PRICE-DATE",
  "ASR_INPUT_PRICE_MICROS": "FILL-POSITIVE-INTEGER",
  "ASR_OUTPUT_PRICE_MICROS": "FILL-POSITIVE-INTEGER",
  "ASR_MAX_INPUT_TOKENS": "32768",
  "ASR_MAX_OUTPUT_TOKENS": "4096",
  "REPORT_API_BASE": "https://YOUR-REPORT-ENDPOINT/v1",
  "REPORT_API_KEY": "YOUR-LOCAL-SECRET",
  "REPORT_MODEL": "YOUR-REPORT-MODEL",
  "REPORT_MODEL_REVISION": "YOUR-PINNED-REVISION",
  "REPORT_PROMPT_VERSION": "teacher-sixdim-v1",
  "REPORT_PROMPT_SHA256": "9b660cfce2c01e717227b381f8876d98106104e10c9c60bfdec17951e4858a55",
  "REPORT_SELECTION_VERSION": "time-window-v1",
  "MODEL_BUDGET_CURRENCY": "CNY",
  "MODEL_BUDGET_TIMEZONE": "Asia/Shanghai",
  "MODEL_MONTHLY_BUDGET": "YOUR-APPROVED-MONTHLY-AMOUNT",
  "MODEL_PRICE_VERSION": "YOUR-PRICE-DATE",
  "MODEL_INPUT_PRICE_PER_MILLION": "FILL-POSITIVE-DECIMAL",
  "MODEL_OUTPUT_PRICE_PER_MILLION": "FILL-POSITIVE-DECIMAL"
}
```

ASR_INPUT_PRICE_MICROS/ASR_OUTPUT_PRICE_MICROS单位是“每百万token的微元价格”：实际人民币单价乘1,000,000后填写整数；报告的MODEL_*_PRICE_PER_MILLION直接填写元。两者共享MODEL_MONTHLY_BUDGET，并使用真实usage结算。每片在发送前按ASR_MAX_INPUT_TOKENS和ASR_MAX_OUTPUT_TOKENS预留；输入上限作为保守费用预留，不能替代供应商实际音频计量说明。超过预留的已知费用会阻断新调用，须管理员核对；不要填写虚假低价来绕过预算。

同一个切片的成功结果会缓存，重试相同字节不再请求供应商。断网、超时或缺少用量时保留unknown费用状态，不自动重复付费。管理员在“运营与账目”核对实际账单并处理后，才决定是否手工新建分析；对账不会补造丢失转写。即使撤权或删除发生在请求发出后，费用仍记录，迟到正文不进入业务结果。

## Windows团队网页启动

先按[原部署说明](../deploy/team-web/README.md)安装Go 1.26、Python 3.12及锁定依赖、Node 24、PostgreSQL 17、模型与前端依赖。保持同一个数据目录；升级前先取消/等待活动分析完成，再停止本部署。将以下路径替换为本机实际位置：

```powershell
python tools/team_web.py --data-root D:/cangjie-data/team-web prepare --go 'C:/Program Files/Go/bin/go.exe' --pg-bin D:/runtime/pgsql/bin --node 'C:/Program Files/nodejs/node.exe' --python D:/vision-env/Scripts/python.exe --models D:/vision-models --analysis-config D:/cangjie-data/team-web/analysis.private.json
$env:TEAM_PYTHON = 'D:/vision-env/Scripts/python.exe'
cmd.exe /c tools\start_team_web.bat D:/cangjie-data/team-web
```

prepare会构建原语言模块为`bin/audio-plan.exe`，仅供本地切片，不启动Demo网页。私有配置路径记入本机private.json，重复prepare保留原凭据和路径。Go缓存、临时文件及启动标记放在可写数据目录，普通Go安装路径不再需要写入Program Files。中文数据目录沿用原有ASCII别名机制；PostgreSQL工具的兼容路径仍按原部署说明处理。

使用`http://127.0.0.1:8088/#/sessions`，账号密码在数据目录的使用说明.txt。先到素材与来源登记并核验，允许analysis和外部处理；需要回放/导出时分别授予对应用途。上传录像后选择“完整分析”，等待转写与报告；“举手与低头分析”仍是独立视觉批次，不生成六维报告。停止与状态命令：

```powershell
python tools/team_web.py --data-root D:/cangjie-data/team-web status
python tools/team_web.py --data-root D:/cangjie-data/team-web stop
```

默认不传--analysis-config的新环境保持视觉模式。已有统一分析环境会保留该私有配置；要返回视觉模式，应在停止后明确移除private.json中的analysis_config字段，再prepare，不要在分析中途换配置。

## 独立部署与容器

Go API读取[配置模板](../.env.example)中的ASR_*和既有REPORT_*/MODEL_*。构建切片工具：

```powershell
cd demos/ai-language-analysis
go build -o ../../var/audio-plan.exe .
cd ../..
```

Worker环境额外设置ASR_PLANNER为上面可执行文件绝对路径，ASR_MODEL_NAME/ASR_MODEL_REVISION与Go一致，WORKER_CAPABILITIES为probe,audio_analysis,video_analysis；WORKER_PROCESSOR_VERSION与FFMPEG_BUILD_SHA256以本机`python -m workers runtime-info`输出为准。继续沿用[Worker启动说明](../workers/README.md)，同一身份独占一个暂存目录，一次执行一个任务。

Worker Dockerfile包含切片工具，默认仍只声明视频能力；显式配置音频能力与模型后才领取音频任务。根Compose仍是后端开发环境，尚未编排前端和Worker；Dockerfile可构建不等于已完成实际容器运行验收。

## 账号权限管理

账号详情可按页读取已有角色及范围，撤销使用现有DELETE接口、登录态和CSRF。学院教务只可管理自己允许的账号范围，不能读取跨学院或受保护账号的绑定；最后一个活动系统管理员继续受到保护。新增授权失败后保留已创建账号，重试授权不会再次创建账号。

## 回归和演示步骤

自动化入口：

```powershell
go test -p 1 -count=1 ./...
python -m pytest -q workers/tests tools/test_team_web.py tools/test_capture_dev.py tools/test_quality.py
python tools/check_docs.py
cd frontend
npm run check
```

Go数据库测试须使用独立TEST_DATABASE_URL；原生数据库验收另设置DATABASE_ACCEPTANCE_URL与ALLOW_RESET，见[数据库验收](数据库联合验收.md)。真实Worker集成另设置WORKER_AUDIO_PYTHON和WORKER_AUDIO_PLANNER，在仓库根目录执行：

```powershell
go test ./internal/httpapi -run '^TestAudioWorkerMainPipeline$' -count=1 -v -timeout=5m
```

该用例使用45秒合成视频、真实FFmpeg和Python Runner、本机模拟模型响应，覆盖带1秒音轨偏移的上传、probe、切片、ASR网关、转写、证据、六维草稿和临时媒体清理。它不会调用收费模型；通过只代表工程流程贯通。

最终演示建议先用获准短录像记录真实耗时，检查转写内容、首中尾时间、六维建议证据，再在前端人工复核发布和导出。视觉结果不能把轨迹数当出勤人数，低头不能直接当不认真。手机流程仍需安卓可信HTTPS、权限、同网互通、实时观看、停止入库和音画同步实机验收，不因电脑合成推流通过就标为完成。

## 备份与恢复

交付前在本机记录代码提交、部署文件、Python/FFmpeg/模型摘要及数据库版本。停止活动任务后，用启动器stop停止本部署全部进程和独立PostgreSQL；确认已停止再对完整数据目录制作受控冷备份，保留postgres-data、media、ledger、private.json和analysis.private.json及其引用位置。模型权重另保留来源和摘要，不把凭据加入Git。

恢复时先保留现有目录，确认没有本部署进程运行，将同版本冷备份恢复到原数据路径，再使用同版本代码及依赖启动。不要将旧备份直接覆盖仍运行的数据库，或单独恢复数据库而遗漏媒体/删除账本。恢复后检查就绪、登录、既有结果回放和一次新短片分析；实际恢复演练属于最终验收，本文不是已经执行成功的证明。
