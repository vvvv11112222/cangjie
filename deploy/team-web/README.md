# 团队网页的本机视觉部署

用于 FR-04/05/06 与 FR-13 的本机试用。复用正式 React 前端、Go API、PostgreSQL 和已交付的视频 Worker；业务页面只访问 Go，Worker 仍经内部租约接口处理任务。本入口是 Windows 开发部署，仅绑定本机，不用于公网生产环境。

## 使用网页

第一次使用请看 [一步步操作指南](使用指南.md)，包含上传后如何开始识别、逐人筛选、录像定位以及“看不清”的含义。

1. 已完成首次准备后，双击仓库根目录的 `启动团队网页.bat`。网页地址为 `http://127.0.0.1:8088/#/sessions`；重复启动不会另起一套服务。
2. 使用 `admin` 登录。密码保存在所选数据目录的 `使用说明.txt`，不写入 Git。`teacher_demo` 等账号仍受已有角色及课堂范围限制。
3. 到“素材与来源”选择课堂、登记录像来源；由有核验权限的人根据真实许可核验，勾选实际允许的播放和分析用途。本部署不会自动核验来源或授予用途。
4. 打开“课堂档案”里的“视觉分析试用课堂”，在“批次与操作”点击“上传录像”，会直接打开文件选择框并定位上传区域。选好文件和来源，再点“提交上传”；上传成功后点“举手与低头分析”。取消文件选择后，表单仍保留，可以重新选文件或点“取消上传”。若要使用之前上传的录像，在“处理目标媒体”中选择它。无需先等 ASR 或配置报告模型。
5. “视觉观察”会自动显示进度和结果。右侧点击人物编号，下面可以筛选“发现举手”“发现低头”，点击“定位录像”，或展开证据图片。历史视觉批次可在同一标签切换。

也可在“课堂档案”列表页点击“上传课堂录像”，选择课堂、已登记的录像来源和文件后开始上传。来源按名称选择，无需填写编号；“1.2”等自编编号不能用于关联来源。来源用于说明录像从哪里来，已有来源可继续使用，没有来源时先到“素材与来源”登记。

红框表示本次检查发现举手，蓝框表示发现低头，绿框表示未见这两种动作，灰框表示看不清。选中人物不会改变行为颜色。播放器上方勾选“显示所有人物框”，首次按分页读取所有编号的既有观察，最多同时读取三个人，完成后缓存于当前打开的记录；取消后只画选中人物，再勾选不重复读取。右侧同步显示当前检查画面中各人的判断，选人仍可查看个人时间记录。读取失败、分页异常或记录不全会明确提示重试，不冒充已读全。

框只在邻近的实际检查时间显示，不将动作补到整段录像；关闭页面或切换批次会丢弃该视图缓存，未开启全班读取时个人记录仍按分页加载。读取全班完成后，个人筛选使用已缓存的完整记录。整班画框不重跑模型，不改变原判断，也不表示覆盖了未检出的人或视频的每一帧。分析等待期间的实时检测画面尚未接入。

## 首次准备

依赖沿用 [Worker 安装说明](../../workers/README.md)：Python 3.12 及锁定依赖、校验后的模型、Go 1.26、PostgreSQL 17、Node 24 和 `frontend` 的 `npm ci`。启动器不下载安装驱动、依赖或模型。

以下示例使用 ASCII 路径；将各个绝对路径替换为本机实际路径，在仓库根目录执行：

```powershell
python tools/team_web.py --data-root D:/cangjie-data/team-web prepare --go D:/runtime/go/bin/go.exe --pg-bin D:/runtime/pgsql/bin --node 'C:/Program Files/nodejs/node.exe' --python D:/vision-env/Scripts/python.exe --models D:/vision-models
$env:TEAM_PYTHON = 'D:/vision-env/Scripts/python.exe'
cmd.exe /c tools\start_team_web.bat D:/cangjie-data/team-web
```

`prepare` 构建正式 Go 和前端、初始化独立数据库、按摘要执行001—010迁移、初始化删除账本、创建开发账号及幂等试用课堂。不会清空数据库、重写迁移或覆盖已有账号密码。已有私有配置会保留凭据。准备新构建前先停止本部署。

Windows 的 PostgreSQL 工具在部分中文路径下无法初始化；使用 ASCII 路径最简便。若必须使用中文路径，在第一次 `prepare` 前用 PowerShell 的原生 `subst.exe` 将运行时根目录和数据根目录分别映射到空闲的 V/W/Y/Z 盘；不要替换其他盘的映射。后续 BAT 启动脚本会通过目录标记复用或重建所需映射。Go、PostgreSQL 可执行文件和数据均使用对应映射。没有空闲盘时明确报错。启动使用普通 BAT，不要求修改 PowerShell 执行策略；可选 PS1 仅适用于本机策略允许的环境。

数据默认在仓库忽略目录 `var/team-web`，也可指定其他项目数据目录。自定义目录时每次传入同一个 `-DataRoot` / `--data-root`；根 BAT 使用默认目录。更换数据目录会连接另一套数据，不是导入旧数据库。

## 服务与停止

| 组件 | 本机端口 / 设置 |
| --- | --- |
| React 已构建页面与同源代理 | 8088，Vite preview，仅作开发试用 |
| Go API | 18088，Cookie/CSRF/Origin 校验沿用正式实现 |
| PostgreSQL | 55437，独立 `cangjie_visual` 数据库 |
| 视频 Worker | 单进程、单任务，CPU / OpenCV 各4线程、batch=1；固定模型及 FFmpeg 版本 |

```powershell
python tools/team_web.py --data-root D:/cangjie-data/team-web status
python tools/team_web.py --data-root D:/cangjie-data/team-web stop
```

分析正在运行时拒绝停止；先在网页取消并等待收口。停止只针对保存了进程身份的本部署进程及其 Worker Job 子进程，不按进程名批量结束。占用端口时拒绝启动，不终止其他服务。`start-detached` 后台启动，关闭启动窗口不会停止分析；电脑重启后需要再次双击 BAT。数据、录像和结果保留在数据目录。

查看 `prepare.log`、`api.log`、`web.log`、`worker.log`、`launcher.log`、`postgres.log` 排障；`deployment.json` 记录提交、模型修订和 CPU 模式。`private.json` 含本机数据库及账号凭据，应留在本地受控目录，不发送给队友或提交仓库。

## 本轮验证与边界（2026-10-19）

- 在真正浏览器中完成登录、来源登记及核验、上传用户提供的2秒课堂片段、点击视觉分析、自动显示结果、人物切换、动作筛选、录像定位和授权证据图片读取。
- 实际 CPU Worker 结果为4次画面检查、49条匿名轨迹、184次人物观察、平均可见人数46.0；有5次人物观察发现举手、持续举手事件0。这些是接口和网页贯通证据，不是人工识别准确率结论；教师、倒影和编号断裂仍可能影响数量。
- 前端276项测试、类型检查及构建；启动生命周期6项边界测试和 PowerShell 语法检查。CI 最终状态见本轮 PR Checks。
- 复用既有0.5秒采样、80人姿态和低头模型，没有为了网页接入减少人数或关闭行为检测。算法与模型未改动；本轮 CPU 真实短片分析仍较慢，不能承诺2分钟录像在2分钟内完成。
- 本机曾发生 NVIDIA 显示驱动故障，本部署固定 CPU，不调用集成或独立显卡推理，不更改驱动、TDR 或系统设置。摄像头、ASR、六维报告和收费模型没有随此启动器启用；原有完整分析入口保留其自身前置条件。
- 页面提供观察与证据，不生成学生综合质量分；低头可能是阅读书写，“看不清”不算“正常”，轨迹数不等于学生人数。独立人工标注质量验收、长录像速度和行为纠正流程仍待完成。

升级或恢复旧试验环境前先核对迁移历史。带未发布同号迁移的数据库不直接套用新迁移；先备份并保留旧库，在独立数据目录部署正式版本。本机旧试验库与媒体已单独保留，不被本部署修改或重置。
