# 上传录像、分析举手低头、查看个人画面

本指南对应团队系统的真实接口模式，沿用原有页面。第一次建议用几秒短片熟悉操作，再分析长录像。

## 1. 打开并登录

双击仓库根目录的 `启动团队网页.bat`，打开 `http://127.0.0.1:8088/#/sessions`。使用部署时创建的账号；本机账号说明保存在所选数据目录的 `使用说明.txt`，不要把该文件发到 GitHub。

## 2. 准备课堂与录像来源

在“课堂档案”选择已有课堂，或者按实际课程新建课堂。

“开课实例”是一学期的授课安排，例如“操作系统、秋季学期、李老师、软件2301班”；“课堂”是其中周一上午的一次上课。到 **教务与课表 → 开课实例 → 新增开课实例** 维护，需先准备课程、学期、教师账号和班级。创建课堂旁的“查看或维护开课实例”可直接进入该标签。名称中的“课堂视觉分析试用 / 本机验收班级”（编号 TEAM-WEB-DEV）是本机试用资料，正式使用应先创建实际开课记录。

新增开课时，“课程”旁点 **输入新课程名称**，可以直接填写新课程名称与课程编码；保存后建立课程并关联本次开课。也可点“改为选择已有课程”。若课程已保存但开课失败，保留填写内容，再保存会复用该课程；取消开课也不会删除已建立课程。修改已有课程的名称请在“课程”标签编辑，以免把一次新开课误当成全校课程重命名。

第一次使用该课堂的录像时，到左侧“素材与来源”：

1. 选择同一节课堂，点“登记新素材”。
2. 填写录像名称、真实来处和许可说明；申请实际需要的“回放”“分析”。本机视觉分析无需勾选外部文本模型，也无需导出。
3. 有核验权限的人根据实际许可保存核验结果。登记不等于取得许可；不确定的用途不要批准。

来源是“这份录像从哪里来、允许做什么”的说明。同一课堂可以复用已有来源；另一课堂须使用属于它自己的来源。

## 3. 上传并开始视觉分析

1. 在课堂档案点击该课堂的“上传录像 →”，进入详情。
2. 在“批次与操作”点击“上传录像”，选择文件、按名称选择已登记来源，点“提交上传”。也可在“素材与来源”直接上传。
3. 从上传流程继续进入课堂时会选中刚上传的录像；也可在“处理目标媒体”中按文件名和上传时间选择。旧录像没有文件名时会明确说明。
4. 点击 **“举手与低头识别”**。即使录像还在等待媒体检查，也可直接点击；系统会先检查和准备录像，再做视觉分析。
5. 页面会切到“视觉观察”，完成后自动显示结果。较长录像需要等待，不要重复提交相同录像。

“语音转写与教学报告”是转写和教师报告的流程，依赖音频与报告配置。只看举手、低头时使用“举手与低头识别”。上传成功只代表录像存进了系统，并不代表已经完成识别。

默认本机视觉部署没有真实语音或报告模型，按钮会显示未就绪原因。免费完整流程测试使用合成模型响应，只证明处理、保存、复核、发布和导出链路可用，不能识别你上传录像中的真实讲话。启用真实模型需要另按[统一接入说明](../../docs/音视频统一接入与收尾.md)配置获准的模型、价格与预算；不因流程测试通过而自动启用收费服务。

### 账号权限在哪里调整

系统管理员进入 **账号与权限 → 账号资料 / 授予新角色**，选择角色并保存；下方“已有角色与授权范围”支持查询和撤销。一个账号可以同时是教师和督导。学院教务仅能管理允许范围内的他人教师、督导账号，不能授予系统管理员或教务角色，也不能修改自己的角色。

在“账号与权限”页点击 **查看角色权限**，可以按表格对照四种角色允许的操作和数据范围；此表只读。真实语音与报告配置可使用仓库根目录 **配置语音与报告.bat**，步骤及费用边界见[模型配置工具](../../docs/模型配置工具.md)。没有自己的模型API密钥时，部署仍保持视觉模式，模拟流程通过不等于已能识别真实讲话。

按项目文档，系统提供四种固定角色，暂不支持自定义角色或逐项勾选权限。谁拥有角色及其范围保存在数据库，允许的操作由后端逐次检查；修改页面文字或浏览器按钮不能增加权限。不能撤销最后一名有效系统管理员。

## 4. 查看某个人什么时候举手或低头

1. 打开课堂详情的 **“视觉观察”**；有多次分析时先选择对应记录。
2. 播放器右侧点击人物编号，例如 T0004。
3. 下方“筛选动作”选择 **“发现举手”** 或 **“发现低头”**。
4. 每一行是系统实际检查过的一张画面。点 **“定位录像”**，会跳到该时间并滚动回播放器。
5. 展开“查看这个时刻的证据图片”，可以核对原画面；图片不可用时仍可查看录像。

如果录像来源只允许“分析”，判断结果仍会保存：选择人物后，左侧直接显示各次检查的时间和判断，可筛选举手或低头。此时不能播放录像或读取证据图片，按钮显示“查看记录”。

需要边看录像边核对时，登记来源时应同时申请“回放”“分析”，再按实际许可核验。只申请过“分析”的旧来源，当前系统不能追加未申请用途；需重新登记包含回放用途的来源并上传录像，旧分析记录保留。不要通过改播放地址绕过用途限制。

编号仅用于这次录像，遮挡或切镜可能使同一个人更换编号，不能直接当成学生学号。

| 画框颜色 | 含义 |
| --- | --- |
| 红色 | 这次检查发现举手 |
| 蓝色 | 这次检查发现低头 |
| 绿色 | 这两种动作都未发现 |
| 灰色 | 至少一种动作看不清，且未发现举手或低头 |

选中人物不会改变动作颜色。在播放器上方勾选 **“显示所有人物框”**，即可同时查看当前检查画面中所有已检出人物的框，右侧同步显示各人的判断。首次需要读取已保存的记录，页面会显示进度；读取完成后播放和拖动录像使用缓存，不会重新分析视频。取消勾选后回到只画选中人物，再次勾选可直接使用缓存。

画框读取失败时可以重试，个人记录仍可查看。切换批次或离开页面后会清除该视图缓存。没有回放许可时不能显示录像框，但分析时间表仍可读取。该开关不补出原模型漏检的人，也不在分析等待期间直播检测画面。

默认每隔0.5秒检查一次，**不是视频的每一帧都检测**。一行“发现举手”不等于举了一次手；相邻多行也可能是同一次持续举手。低头可能是在阅读、写字，不直接等于不认真。可见人数、人物编号数量也不等于出勤人数。

## 5. 找不到结果时先看这里

| 看到的情况 | 下一步 |
| --- | --- |
| 上传后没有识别结果 | 选择处理目标媒体，再点“举手与低头识别” |
| 分析按钮不能点 | 先选择录像，检查来源是否已核验且允许分析 |
| “发现举手”筛选没有行 | 换人物检查；有“继续读取这个人的记录”时先读取剩余记录。空筛选不证明整段录像没人举手 |
| 有编号但灰框很多 | 该人物手臂、脸部太小或被遮挡，系统无法可靠判断 |
| 没有画框 | 先定位某一条记录；未加载或未检查的时间不补画框 |
| 历史录像看不到 | 核对课堂、处理录像和视觉分析记录是否选对 |
| 课堂处于“彻底清理中” | 已停止提供内容读取；不要继续对这节课堂上传或分析，改用其他课堂。清理失败需由管理员排查 |

“彻底清理课堂”用于永久移除整节课堂及相关内容，不能用作清空筛选或重做分析。需要再分析时创建新批次；只是暂时不想显示课堂时使用归档。

安装、停止、配置及验收限制见 [本机部署说明](README.md)。


## 首次使用与处理服务检查

教学工作台和课堂档案提供“上传录像并分析”“使用手机录制”入口。上传区域内可登记来源，有核验权限时可按真实许可核验，选好的文件会保留。上传成功后进入对应录像的分析选择，系统不会自动发起收费调用。

分析入口会检查处理服务和预算，说明缺少什么以及联系谁处理。状态读取失败时请点击“重新检查服务状态”；未启用的功能不能提交新任务。语音与报告还要求来源允许向云端发送音频、文本；默认视觉部署没有启用该能力。视觉固定模型补齐后应重启Worker，页面随后重新检查。

转写和报告显示对应录像、分析提交时间及版本。报告按“草稿与提交复核→逐条处理观察→确认整篇内容→发布报告→按用途导出”指引下一步；当前账号不能处理时会说明负责角色。修改正文后要重新复核和确认。

## 在网页配置语音与教学报告模型

使用系统管理员账号进入“运行与设置”，在“语音与报告模型配置”填写接口基础地址、模型名称及实际修订、密钥、token单价、价格来源和共享月预算。报告模板由系统固定。已有密钥只显示已设置；留空保留，清除需要明确勾选，地址变化时需重新填写。核对实际价格并勾选确认、填写变更说明后点击“保存并应用模型配置”。

有排队或运行分析、未知费用或未核对超额账目时暂不能应用；先完成或取消任务并处理账单，再重新读取状态。成功后后续新分析立即使用新配置，无需手动重启；历史结果保留原版本。保存不调用云模型，不等同于已验证连通性。随后在具体课堂选择获准云端处理的录像，提交“语音转写与教学报告”。
